How TruthFeed works

TruthFeed is a subjective-question oracle deployed on GenLayer: an intelligent contract that turns “will X happen?” into an auditable, on-chain verdict reached by independent LLM validators.

What is TruthFeed?

Smart contracts can read balances and block hashes — but not the answer to “did the launch ship before March 31?” TruthFeed closes that gap. Anyone posts a yes/no question with plain-language resolution criteria and 1–5 source URLs. The contract fetches those pages itself, asks a large language model to judge them against the criteria, and settles a verdict of YES, NO, or UNCLEAR. The outcome, cited source numbers, and a clearly labeled leader rationale are stored on-chain.

Once resolved, an outcome becomes reusable truth: other contracts (prediction markets, parametric insurance, escrow) can read it synchronously via cross-contract views.

Why does a blockchain need LLM validators here?

A chain has no trusted oracle for subjective judgment — no single node you could ask “what does this page say?” without trusting that one node. TruthFeed instead runs its prompt through GenLayer's validator consensus: one leader fetches the sources and judges them with an LLM, then every validator independently re-fetches and re-judges with their own model. Validators compare the outcome and canonical source citations; free-form rationale is not a consensus field. A leader who keeps failing is rotated out. The result is a verdict no single party — and no single LLM — could have dictated.

Using this dApp

  1. Connect Wallet. Click Connect Wallet in the header and approve the prompt in your browser wallet (MetaMask). MetaMask auto-adds the GenLayer Studio network (chain 61999) if it is missing — no manual setup.
  2. Get testnet GEN. Studionet is gasless-friendly — any studio test account with funds works. Top up at GenLayer Studio if needed.
  3. Ask. Write a yes/no question, precise criteria, and 1–5 HTTPS sources. Optionally schedule the earliest resolution time.
  4. Resolve. Hit Resolve on any open question. Validators fetch, judge and vote — expect a short wait while consensus runs.
  5. Read the verdict. The card shows YES / NO / UNCLEAR and the consensus source numbers. The prose underneath is the leader rationale, not a consensus field.
  6. Recheck if needed. The question creator can request a new resolution after finality; every earlier decision remains in history.

FAQ

What stops a malicious leader from forcing its own answer?

Nothing is taken from the leader on faith: every validator re-runs the same fetch-and-judge pipeline and compares outcome + canonical source citations against the leader's. On disagreement the vote fails and the network rotates to a new leader. A malicious leader must therefore out-vote the entire committee, round after round — economically irrational by design.

Can outcomes change after they settle?

A completed decision is never overwritten. The creator can request another round, but the earlier outcome, citations, rationale, and timestamp stay in the on-chain history.

What if a source page goes down mid-consensus?

Fetch failures degrade gracefully: an unavailable page is fed to the judge as “source temporarily unavailable”, which typically yields UNCLEAR rather than a wrong or crashed resolution. Transient errors are agreed on as a class, never punished.

Does this site ever see my private key?

No. Transactions are signed inside your own browser wallet (MetaMask); TruthFeed only ever receives the resulting signature. The connected address is kept in this tab's sessionStorage for convenience and disappears when you hit Disconnect or close the tab.
