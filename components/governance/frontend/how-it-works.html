Mechanism

Prose that enforces itself.

LivingConstitution stores a DAO's constitution as natural language — then makes it binding. Every proposal is judged against the charter by independent LLM validators before it can move forward.

§1. What is LivingConstitution?

A GenLayer intelligent contract: a smart contract whose logic calls a large language model. The charter lives on-chain as text (versioned, owner-amendable). Proposals are text too. When a proposal is checked, the network's validators each run the same prompt — judge this proposal against this charter — and consensus forces them to agree on the verdict before anything settles.

§2. The problem

DAO constitutions are prose. Enforcement is manual: a committee reads proposals, argues about interpretation, and applies rules inconsistently — or ignores them under pressure. Rules that live in PDFs don't execute. LivingConstitution moves the charter from the PDF to the consensus layer, where ignoring it is not an option.

§3. How it works

1

Amend charter

The owner appends a new version of the constitution text. Old versions stay archived on-chain.

↓
2

Submit proposal

Anyone with a connected browser wallet registers a title + body. The proposal is pinned to the current constitution version.

↓
3

Validators judge independently

On check, validators independently return compliant, non_compliant, or needs_review with canonical rule references.

↓
4

Equivalence principle

GenLayer requires agreement on both the verdict and canonical rule references. A mismatch rotates the leader.

↓
5

Review is accepted, then finalized

The agreed verdict + rule references are authoritative. The leader rationale is labeled separately. Transaction finality is tracked separately from the decision.

↓
6

Compliant proposals may enter a ballot

The proposal creator can open a time-bounded, one-wallet/one-vote pilot ballot pinned to that review. Its quorum and duration come from the fixed contract policy. A recheck cannot cancel an active vote.

§4. Using this dApp

  1. Connect Wallet. MetaMask adds the GenLayer Studio network automatically — approve the prompts and you're connected. Connecting is the only way to submit or check proposals; only your public address is stored (in sessionStorage) and keys never touch this page.
  2. Submit a proposal. Title + body get a random p-xxxxxx id and settle as an ordinary transaction.
  3. Run the check. Press Run constitutional check. Validators review the text against the charter — this takes longer than a normal transaction because LLM consensus is running.
  4. Read the verdict. The card shows COMPLIANT, NON-COMPLIANT, or NEEDS REVIEW with consensus rule references and a separately labeled leader rationale.
  5. Request a recheck. The proposal creator provides a reason and reopens a checked proposal under the latest constitution without erasing earlier reviews.
  6. Open and vote. The creator opens voting for a compliant proposal. One wallet can cast one FOR or AGAINST vote.
  7. Search both products. The Decision Registry combines this contract with TruthFeed and shows the latest tracked transaction status. The index is not the source of truth.

§6. FAQ

What if validators disagree?

The equivalence principle treats disagreement as failure: the leader rotates until the verdict and canonical rule-reference set match.

Who amends the charter?

The current StudioNet deployer owns amendments via update_constitution. Transfer is two-step: a Safe, multisig, or DAO executor is nominated, then that destination must accept.

Can a compliant proposal still lose a vote?

Yes. Compliance only opens the gate. The separate ballot still needs quorum and more FOR than AGAINST votes.

Can I use a native GenLayer appeal on StudioNet?

No. StudioNet does not expose the appeals, fee-manager, or rounds-storage contracts. This pilot offers an application-level reasoned recheck and preserves every earlier ruling. Native bonded appeals can be added when deployed to a supported public network.
